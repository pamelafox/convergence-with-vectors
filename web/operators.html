How the combination operators work

Every operator answers the same question: which word sits between word A and word B? Each candidate word w gets two numbers: how similar it is to A (sa = cos(w, a)) and how similar it is to B (sb = cos(w, b)). The operators differ only in how they turn those two numbers into one score.

2. Try your own numbers

Pretend a candidate word has these two similarities, and see how each operator scores it. The orange ring on the plot above moves with the sliders.

Mean lets a big similarity make up for a small one. Balanced only counts the weaker one, so a word has to relate to both inputs. Geometric mean is in between: lopsided pairs are penalized, but the stronger side still counts.

When both numbers are non-negative, balanced ≤ geometric mean ≤ mean, and all three are equal only when sa = sb.

Geometric mean sets negative similarities to 0 before multiplying. Without that, a word unrelated to both inputs (−0.3 × −0.3 = +0.09) would get a positive score.

3. Why centroid ranks words the same way as mean

Centroid adds the two vectors, rescales the sum to length 1 to get ĉ, and finds the word closest to ĉ. Because every vector has length 1, the dot product splits into two parts:

cos(w, ĉ) = w·(a + b) / ‖a + b‖ = (sa + sb) / ‖a + b‖

‖a + b‖ depends only on A and B, so it is the same number for every candidate:

Dividing every score by the same number doesn't change which word wins, so centroid and mean always pick the same words. The only difference is the scale: on the plot, both operators have straight diagonal lines of equal score.

What about textual?

The fifth operator in operators.py skips the vector arithmetic. It embeds a phrase like "fire and whale" and finds the word closest to that phrase's vector. The transformer reads both words together, so it can capture a combined meaning that a plain average can't. It needs the model at run time to embed the new phrase, though, so it can't run on this static page. Try it with uv run compare_pair.py instead.
