Let's play Convergence

  1. Two players face each other.
  2. Everyone counts down, "3..2..1"
  3. They both yell a word at the same time,
    like "fire" and "whale".
  4. Everyone thinks:
    "What single word is between those two words?"
  5. Two new players count down and yell their words,
    like "blubber" and "engine".
  6. Same word? Everyone wins! 🎉
    Different words? Keep going.
Introduce the game from improv class. Emphasize: you can't plan, you can only think about the two words. Pick two volunteers. Write the starting words down: they'll be the models' starting words next.

Words as vectors

Vector embeddings

Vector embeddings are lists of numbers that represent items in a high-dimensional space.

Each number is a dimension.

An embedding model turns text into a vector:

"fire" → embedding model →
[-0.030, 0.089, 0.008, 0.048, 0.026, …]

Generate embeddings with Python

Download model weights from Hugging Face
and generate embeddings with SentenceTransformer:


from sentence_transformers import SentenceTransformer

model = SentenceTransformer(
    "sentence-transformers/all-MiniLM-L6-v2")

vectors = model.encode(["fire", "whale"],
                       normalize_embeddings=True)
print(vectors.shape)  # (2, 384)

Measuring vector similarity

The most popular method is cosine similarity.


fire, whale = model.encode(
    ["fire", "whale"],
    normalize_embeddings=True)
fire[-0.030, 0.089, …]
whale[-0.026, 0.061, …]

# Cosine similarity
np.dot(fire, whale) / (
    np.linalg.norm(fire) *
    np.linalg.norm(whale))  # 0.30
\[\frac{\color{#c2410c}{\mathbf{x}} \cdot \color{#3776ab}{\mathbf{y}}}{\lVert\color{#c2410c}{\mathbf{x}}\rVert \, \lVert\color{#3776ab}{\mathbf{y}}\rVert}\]

# Dot product for unit vectors
np.dot(fire, whale)  # 0.30

Where two words meet

Operator 1: Centroid

Find the word closest to the average vector.


query = normalize(vec_a + vec_b)
scores = np.dot(vocab.vectors, query)

Effectively sums s_a + s_b, so one very high similarity can win.

Operator 2: Maximin

Find the word whose weaker similarity is highest.


scores = np.minimum(sim_a, sim_b)

Maximize the minimum similarity.

Each circle is a similarity cutoff: "within 64 degrees of earring" is the same as "similarity to earring at least 0.44", since cosine similarity is the cosine of the angle. Growing both circles lowers the bar for both words at once. The first word inside both circles is the one whose weaker similarity is highest: telephone, at 0.44, the bold number in the table.

Operator 3: Product

Find the word with the highest product of similarities.


scores = (np.clip(sim_a, 0, None) *
          np.clip(sim_b, 0, None))

The biggest rectangle s_a × s_b wins, so one low similarity hurts.

Operator 4: Textual

Let the model combine them: embed a phrase.


phrase = f"{word_a} and {word_b}"
phrase_vec = model.encode(
    [phrase], normalize_embeddings=True)[0]
scores = np.dot(vocab.vectors, phrase_vec)

Playing the game

The game, step by step

  1. Start with two words, a and b.
  2. Two models each pick their top word with the same operator.
  3. Same word? Converged! 🎉
  4. Different words? Those two picks become the next pair.
  5. Stop if a pair repeats (loop) or after 10 rounds.
Candidates come from a vocabulary of 5000 concrete nouns, embedded once per model.

The game loop


pair = (word_a, word_b)
for round_number in range(1, max_rounds + 1):
    # Each model picks its top word, excluding the pair
    picks = tuple(top_word(model, operator, pair)
                  for model in (model_a, model_b))
    if picks[0] == picks[1]:
        return "converged", round_number
    if picks in seen:
        return "loop", round_number
    seen.add(picks)
    pair = picks
return "round_limit", max_rounds

Self-play: instant convergence

A model vs. itself converges in round 1, every time.

Same vectors + same math = same word.

Convergence is only interesting when the players see the world differently.

Does the operator matter?

OperatorConvergedAvg roundsLoopsRound limit
Centroid87%2.713%0%
Textual86%2.814%0%
Product84%3.114%2%
Maximin51%4.522%26%
Why does maximin do so badly? Centroid can win with a word very close to one input, like a near-synonym, and models tend to agree on near-synonyms. Maximin has to find a word that works for both inputs, and those "bridge" words are where models' views of the world differ most. In round 1, two different models pick the same maximin word only 4% of the time, vs. 21% for centroid.

Vectors have a day job

Vector embeddings are the technology powering:

🔍Semantic search
Find documents by meaning, not keywords
🤖RAG
Retrieve relevant context for LLM answers
🛍️Recommendations
Suggest items similar to ones you liked
🧹Clustering
Group similar items, spot duplicates
